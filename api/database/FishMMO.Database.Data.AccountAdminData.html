Remarks

This type must never carry Salt, Verifier, TotpSecret, VerifyCode or DiscordLinkCode. AccountData carries all of them because the login path is the one caller that needs them: SRP cannot verify a password without the salt and the verifier, and the TOTP check cannot run without the secret. An operator view that carried the same fields would put every account's password material — and every account's second factor — behind nothing but an access-level check, on a surface that is read by a panel, serialized to JSON, and logged. The whole point of SRP is that the verifier never leaves the authentication path; a stolen verifier is an offline dictionary attack against that account with no further access needed, and a stolen TOTP secret makes the second factor forgeable forever.

That is precisely why this is a separate type and not a projection, a subset view, or a nullable-ed copy of AccountData. A projection is one careless MapEntityToDto edit away from leaking, and the leak would be invisible at the call site. A type that has no such field cannot leak it, and a future field added to AccountData does not silently appear here.

TotpEnabled and TotpVerifiedAt are safe and are deliberately kept: an operator answering "why can this person not sign in" needs to know whether a second factor is in the way, and neither field helps forge a code.
