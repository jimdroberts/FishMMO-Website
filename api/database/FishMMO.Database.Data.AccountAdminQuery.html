Remarks

An object rather than a parameter list because this grows: every new filter the panel gains would otherwise be another overload or another positional bool that reads identically to the one beside it at the call site.

IncludeBanned

Whether banned accounts appear in the results. Defaults to true.

public bool IncludeBanned { get; set; }

Property Value

bool

Remarks

True by default because the operator searching for an account is most often searching for one they just banned, or one they are about to unban. Hiding those by default would make the common case look like the account had vanished.

Query

Name or email prefix to match, or null/empty for no text filter.

public string? Query { get; set; }

Remarks

A prefix, not a substring. See the search implementation for why: a leading wildcard forecloses any use of the indexes on name_lowercase and email, and guaranteeing a full-table scan is not something a search box gets to do.
