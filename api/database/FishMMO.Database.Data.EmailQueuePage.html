Remarks

OldestPendingCreatedAt is the number this whole read exists for. Account verification reaches a player through this table and nothing else. When no login server is claiming rows — the process is down, SMTP is refusing, the credentials expired — registration stops working for every new account, and there is no other symptom: the website accepts the registration, the row is written, and the player simply never gets their mail. A depth count does not show it either, because a healthy queue and a dead one both read as a small number on a quiet shard. The age of the oldest unclaimed row is what separates them, and it is the one value on this page an operator should be alarmed by.

Both ages are supplied because they answer different questions. OldestPendingCreatedAt asks whether anything is draining the queue. OldestUnsentCreatedAt asks how long the longest-waiting account has been waiting, which includes rows a login server claimed and then stopped reporting on — those are stuck too, and a pending-only number would show zero while they sat there forever.

Remarks

The ages above are differences against this instant, computed by the caller rather than stored. It is the database's time because the database stamps created_at (a column default), so both sides of every age come from one clock and a panel clock that disagrees with the database's cannot turn a young queue into an alarm or an old one into silence. It used to be the panel's own DateTime.UtcNow, and the alarm moved with the panel host's clock.
