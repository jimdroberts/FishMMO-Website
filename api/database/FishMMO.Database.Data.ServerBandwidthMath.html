CurrentFreshSeconds

A server's latest minute counts as its current rate only while it is at most this old by the database clock. A server samples every 60 seconds, so a live one is never more than two minutes behind; five leaves room for a deferred sample.

public const int CurrentFreshSeconds = 300

IpV4UdpHeaderBytes

IPv4 (20) plus UDP (8) header bytes per datagram, the difference between msquic's UDP payload count and the bytes on the wire.

public const int IpV4UdpHeaderBytes = 28

Field Value

int

Remarks

The same constant as TransportTrafficMath.IpV4UdpHeaderBytes in the WebTransport plugin, which this assembly cannot reference; a test pins them equal. The native stack binds IPv4 only. Ethernet framing is deliberately not added: egress is billed at the IP level.

MaxPendingMinutes

The most minutes a server process holds for retry while the database refuses its writes; older ones are dropped, and the drop is logged.

public const int MaxPendingMinutes = 60

Field Value

int

MinuteRetentionDays

How long minute rows are kept before the rollup job folds and deletes them.

public const int MinuteRetentionDays = 14

Field Value

int

RollupWindowHours

How many trailing hours every rollup pass recomputes, the current one included.

public const int RollupWindowHours = 6

Field Value

int

Remarks

A server holds a minute it could not write and retries it for up to MaxPendingMinutes, so a minute row can land that long after its minute. The window has to reach further back than that, or the hour it belongs to would have been rolled for the last time before the row arrived.

StitchHours

How far behind the current hour the 30-day figures stop reading hour rows and start reading minutes, so they never depend on the rollup having run in the last few minutes.

public const int StitchHours = 3

int
