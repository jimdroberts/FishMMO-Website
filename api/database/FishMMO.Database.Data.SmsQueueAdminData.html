Remarks

The SMS twin of EmailQueueAdminData. sms_queue has the same three delivery columns as email_queue, so its state is the same combination and is classified by the same EmailQueueState rather than a copy of it that could drift: a filter, a count and a badge must mean one thing across both queues.

The body is deliberately absent, for the reason the email body is: a verification text is a one-time code, and whoever reads it can prove a phone number they do not hold. The projection never names the column.

RecipientPhone is the full number and is personal data. It stops at the panel's controller, which sends the browser a masked form only; nothing on the page needs the whole number to answer "did this player's code go out".
