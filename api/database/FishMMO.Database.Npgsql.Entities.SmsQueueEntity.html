Outbound text message queue. Messages are inserted by the application layer and picked up by a background sender. Failed deliveries are retried up to a configurable maximum.

Remarks

Shaped exactly like EmailQueueEntity, claim columns and all, so one drain pattern serves both and a player choosing verify-by-SMS goes through the same queue semantics as one choosing email.

There is no SMS provider yet; the sender that drains this table only logs. The queue exists now so that callers record what would be sent, and adding a provider later changes the drain rather than every caller.

Remarks

Bounded because a text message is billed per segment: an unbounded body is an unbounded bill for one enqueue. 480 is room for a code and a sentence with plenty to spare.
