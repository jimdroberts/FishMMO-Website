Remarks

World time is "world milliseconds since the calendar epoch", and it is never stored as a running value. The row is an anchor: at database time BaseReferenceMs the world read BaseWorldMs, and it has advanced at Rate world seconds per real second since. World ms now = base_world_ms + rate × (db_now_ms − base_reference_ms), computed in SQL against the database clock, so every reader agrees on it whatever its own clock says. See WorldClockControlService.

Every write re-anchors at the moment it is made and bumps Revision. A scene server that reads a new revision treats it as an instant jump rather than smoothing towards it — that is what an admin setting the time asked for.

No xmin token: every write is one raw UPDATE … RETURNING that computes from the row it locks, so there is no read-modify-write for a token to protect.
