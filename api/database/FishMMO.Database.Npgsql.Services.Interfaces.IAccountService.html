Service interface for account operations following ISP principle. All operations are async and return DatabaseResult for consistent error handling. Implements execution strategies for automatic retry on transient database failures.

public interface IAccountService : IExistsByKeyAction<string>
Inherited Members
IExistsByKeyAction<string>.ExistsAsync(string, CancellationToken)

Remarks

This service provides account management operations including:

  • Account creation with atomic UPSERT to prevent race conditions
  • Login authentication with SRP (Secure Remote Password) protocol support
  • Last login timestamp tracking
  • Account existence checks

Methods that perform database write operations use execution strategies to automatically retry on transient failures (up to 3 attempts by default). This includes connection timeouts, deadlocks, and network interruptions.

All methods follow consistent validation and error handling patterns:

  • Username validation (3-32 characters, non-empty)
  • Null safety with nullable reference types
  • DatabaseResult pattern for safe, typed error handling
  • Custom exceptions with sanitized messages for security

BanAsync(string, DateTime?, string?, string?, CancellationToken)

Bans an account: drops it to AccessLevel.Banned, revokes its auth tokens and Control Panel sessions, queues a kick so the game servers disconnect it, and records who banned it, why, and when the ban lifts.

Task<DatabaseResult> BanAsync(string accountName, DateTime? bannedUntilUtc, string? bannedBy, string? reason, CancellationToken cancellationToken = default)

Parameters

accountName string

Account to ban. Matched case-insensitively.

bannedUntilUtc DateTime?

When the ban lifts, or null for a permanent ban.

bannedBy string

Operator account applying the ban, or null when not recorded.

reason string

The reason, or null when not recorded.

cancellationToken CancellationToken

Cancellation token.

Returns

Task<DatabaseResult>

Success, or DB_NOT_FOUND when no such account exists.

Remarks

All four writes land together or none of them do. A half-applied ban leaves the account playing: the access level is the login gate and nothing else, so lowering it alone stops the next sign-in and does nothing to the session already connected, while revoking tokens alone lets the player sign straight back in. The failure this atomicity exists to prevent is exactly that — an operator who is told the ban succeeded, watching the banned account keep playing.

This layer does no policy checking. Who may ban whom is the caller's decision, and every caller must record the ban in the audit log.

A null bannedUntilUtc is a permanent ban. A temporary one is lifted by FetchForLoginAsync(string, bool, CancellationToken) at the first sign-in attempt after the instant passes, which restores Player.

The only ban. A one-argument overload that recorded neither actor nor reason was removed (issue #267): an account page showing "banned by: —, reason: —" is a ban nobody can explain or appeal, and every real caller already passed both.

  • (Banned, null): Account exists but is banned Success: Returns AccountData with salt, verifier, access level, and timestamps. Failure cases:

verifyCode int
cancellationToken CancellationToken

Returns

The channel or channels the code proved.

Remarks

The code is matched against every code the account holds — email, SMS and Discord — and a match on any one of them verifies the account. The update also clears every other outstanding code and the failed-code count. A Discord match links the account to the Discord user the DM reached, unless that user is already linked to a different account, in which case it does not match.

Only an unverified account can match. A wrong code, an expired one, an unknown account and a verified account all fail with the same validation error.

UnbanAsync(string, CancellationToken)

Lifts a ban by restoring AccessLevel.Player.

Task<DatabaseResult> UnbanAsync(string accountName, CancellationToken cancellationToken = default)

Parameters

accountName string

Account to unban. Matched case-insensitively.

cancellationToken CancellationToken

Cancellation token.

Returns

Task<DatabaseResult>

Success, or DB_NOT_FOUND when no such account exists.

Remarks

Deliberately not the inverse of BanAsync(string, DateTime?, string?, string?, CancellationToken). It restores the level and nothing else: the auth tokens and panel sessions the ban revoked are correctly gone, and reviving them would hand back credentials that may well be the reason for the ban and have since been shared or stolen. The player signs in again, which re-issues everything through the paths that are allowed to mint it.

It restores Player specifically, not whatever the level was before. This layer does not record the previous level, and guessing wrong in the upward direction would silently hand back operator access.
