DeleteAbilityAsync(long, long, long, CancellationToken)

Removes one ability outright, so the character may craft the same template again.

Task<DatabaseResult> DeleteAbilityAsync(long characterId, long abilityId, long incomingVersion, CancellationToken cancellationToken = default)

Parameters

characterId long

The character that owns the ability. Checked, so one character cannot delete another's row.

abilityId long

The row identity, never the template id.

incomingVersion long

The authoritative, monotonic version for this delete. The row is removed when its own version is at or below this.

cancellationToken CancellationToken

Token to cancel the operation.

Returns

Task<DatabaseResult>

Remarks

Distinct from DeleteAsync(long, long, long, CancellationToken), which leaves a tombstone. A forgotten ability is not a record of anything — it is the character no longer having it — and the tombstone is what would stand in the way of re-crafting it. The upsert keys on (character_id, template_id) and refuses to drop below the surviving row's version, so a soft delete that stamped the caller's version into the row would leave it holding a version no fresh craft could outrank, and the upsert's own id <= 0 guard would then reject the re-craft as a stale write. Forget-then-craft is a flow the craft panel explicitly advertises.

This mirrors ICharacterItemService.DeleteItemAsync, which removed a vacated row outright for the same reason.

DeleteAbilityOwnedAsync(long, long, long, CharacterSessionLeaseData, bool, CancellationToken)

DeleteAbilityAsync(long, long, long, CancellationToken), admitted only while the writer still holds the character's session claim.

Task<DatabaseResult> DeleteAbilityOwnedAsync(long characterId, long abilityId, long incomingVersion, CharacterSessionLeaseData claim, bool admitReleased = false, CancellationToken cancellationToken = default)

Parameters

characterId long

The character that owns the ability.

abilityId long

The row identity, never the template id.

incomingVersion long

The version ceiling; the row is removed when its own version is at or below this.

claim CharacterSessionLeaseData

The claim the delete was captured under. Must name characterId.

admitReleased bool

Also admit an unclaimed character. Only for undoing the writer's own row.

cancellationToken CancellationToken

Token to cancel the operation.

Returns

Task<DatabaseResult>

Success when the row is gone. Fails with Forbidden when the claim is not held (see admitReleased).

Remarks

The forget a resident character asks for. The claim is checked, under the character's share lock, in the delete's own transaction — see CharacterWriteGate.

admitReleased is for a delete that UNDOES a row the same writer wrote under claim (the grant's revoke): it is then also admitted while the character holds no claim at all, released and not yet claimed again, because the character may have left before the revoke could run and nobody has the row loaded. It is still refused once another session holds the character.

PersistOwnedAsync(CharacterAbilityData, CharacterSessionLeaseData, CancellationToken)

Persists one ability row, and returns its identity, only while the writer still holds the character's session claim.

Task<DatabaseResult<long>> PersistOwnedAsync(CharacterAbilityData abilityData, CharacterSessionLeaseData claim, CancellationToken cancellationToken = default)

Parameters

abilityData CharacterAbilityData

The row.

claim CharacterSessionLeaseData

The claim the write was captured under. Must name the row's character.

cancellationToken CancellationToken

Token to cancel the operation.

Returns

Task<DatabaseResult<long>>

The row's identity. Fails with Forbidden when the claim is no longer held, and with NotFound when the character is gone.

Remarks

The single-row sibling of PersistOwnedAsync(IEnumerable<TItem>, IReadOnlyCollection<CharacterSessionLeaseData>, CancellationToken), for a grant made while the character is resident: the claim is captured with the request and checked, under the character's share lock, in the write's own transaction — see CharacterWriteGate. The ungated PersistAsync(TRequest, CancellationToken) remains for writers that hold no claim by design.
