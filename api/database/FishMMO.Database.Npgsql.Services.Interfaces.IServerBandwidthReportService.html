The operator's side of the bandwidth tables: the page's read, and the rollup and retention the Control Panel runs on a timer.

public interface IServerBandwidthReportService

Remarks

One pass at a time across every panel. The rollup and each retention batch run in a transaction that first takes pg_try_advisory_xact_lock; a panel that does not get it skips the pass. The numbers would be right without it — every hour row is recomputed from its minutes and SET, never added to — but two panels upserting the same hour rows in whatever order their GROUP BY produced can deadlock each other, and two retention passes would fight over the same victims. It is a TRANSACTION-level lock on purpose: pooled connections are returned without a reset (NoResetOnClose), so a session-level lock would outlive the pass on a connection somebody else later borrows.

Remarks

Minutes go one whole hour per transaction, and that transaction first rolls the hour it is about to delete, so pruning can never lose traffic the rollup had not reached, and no hour is ever left with some of its minutes gone (which a later recompute would read as a smaller hour).
