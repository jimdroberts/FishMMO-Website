Remarks

Nothing here is undoable. Removing PostgreSQL deletes the cluster data directory, and that directory is every account, character, guild, item and audit row the deployment has ever had. There is no recycle bin and no second copy. The confirmation flow is therefore the feature, not the packaging around it:

  1. Resolve the real commands and the real paths for this machine and show them.
  2. Say which services are running that will break the moment the database is gone.
  3. Offer a dump first, and stop dead if the dump is asked for and fails.
  4. Require a typed phrase nobody types by reflex — not a keypress.
  5. Run the steps in order, stop at the first real failure, and report every outcome, so a half-done uninstall is visible rather than silent.

The command and path resolution lives in UninstallPlanner, which touches nothing and can be asserted on its own. This file is the part that talks to the operator and runs what the planner decided.
