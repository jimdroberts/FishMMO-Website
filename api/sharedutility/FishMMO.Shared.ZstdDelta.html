Remarks

Used by the native client patches: the patch generator stores each changed file as a delta against the version the player already has, and the Updater rebuilds the new file from the old one plus the delta. Unlike a same-offset chunk diff, a zstd match can point anywhere in the old file, so inserted or removed bytes do not invalidate everything after them; and a file Addressables renamed because a dependency's name inside it changed costs a few kilobytes instead of its whole size.

The reference file is memory-mapped and handed to zstd as a prefix, so neither side copies it into managed memory. A frame is a single zstd frame with the content size and a checksum, readable by the stock zstd tool (zstd -d --patch-from=old delta).

The window is sized from the larger of the two files, capped at MaxWindowLog (1 GiB), the largest window every decoder, 32-bit included, accepts. A file larger than MaxReferenceBytes cannot be referenced in full; callers ship such files whole (see CanReference(long, long)).
