Remarks

The same boxes the server enforces. The scene server checks SceneBoundaryDetails.ContainsPoint: axis-aligned boxes, inside any one of them is inside. This reads the scene's SceneBoundary components — what that cache is built from — and measures the same boxes, so the glass stands exactly where the server will stop the player. A face shared with a neighbouring box is not an edge, and shows nothing.

One break, set entirely by distance. Each frame the shader is told where on the face the player's chest is, how hard they are pressing (from how close they are), and how much of the invisible force a metre or two short of the boundary is on. The fracture pattern itself is fixed to the face, so walking closer breaks it further, backing off eases it back, and walking along the wall carries the break through the pattern. Nothing is timed, so nothing restarts. The look is FishMMO/Boundary Glass; see RequestSceneTextures(bool) for what its refraction costs and when.

Every face, the ceiling included. A flier meets the top of the box the same way a walker meets a side, and sees the same glass overhead.

Whose glass it is. Initialize() follows the local player's character as it starts and stops; Initialize(Transform) follows one transform for as long as its owner keeps it, which is how the world test bed shows the glass round its walker, with no player and no client. Either way the owner calls Tick() once a frame and Shutdown() when done, which takes the panes down and gives the camera back.

Presentation only: it never moves the player or blocks anything. Client-only by assembly: FishMMO.Client is not compiled into the server.
