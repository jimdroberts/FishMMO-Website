Remarks

Overlays, never edits. Every one of these systems takes its budget from the Weather Render Profile, a ScriptableObject: writing a player's choice into it would, in the editor, rewrite the asset. So each setting is read where the system reads its profile and combined with it there (switched off, or a different tier's numbers), and the profile is left as authored.

Levels are tiers. A VisualLevel other than Auto picks which Quality preset's numbers a system uses (TierLevel(VisualLevel) → WeatherRenderProfile.TierFor), so Low clouds on the High Fidelity preset are exactly the Performant preset's clouds: values already tuned and measured, not a multiplier nobody has looked at.

Read every frame, cheaply. The values are read from the settings store once per frame at most and held, so a system asking several times a frame pays a field read; a change made in the options panel, a profile load or a reset is picked up on the next frame.
