Remarks

Kept apart from MapMarkerFilter because the questions are different. The filter's job is to decide what a player is allowed to know about other entities, and everything in it is about relationships, ranges and staleness. Nothing here is a secret from anybody: a landmark is scene data and a note is something the player wrote. Mixing them would put content with no visibility rules through a class whose entire purpose is visibility rules.

Remarks

A fixed palette rather than a colour picker. The pins are drawn at fourteen points over terrain of every possible hue, and a player who picks their own colour will eventually pick one that is invisible against the ground they put it on. These are chosen to stay legible against both the dark water and the bright sand a map contains.

AppendPointsOfInterest(List<MapMarkerSnapshot>, WorldSceneDetails, WorldMapDefinition, FogOfWarMap, bool, int)

Adds a scene's points of interest to a snapshot list: the scene details' own list first, then the map definition's, each landmark once.

public static void AppendPointsOfInterest(List<MapMarkerSnapshot> results, WorldSceneDetails details, WorldMapDefinition definition, FogOfWarMap fog, bool forWorldMap, int labelTier = 2147483647)

Parameters

results List<MapMarkerSnapshot>

The list to append to.

details WorldSceneDetails

The scene's details, holding its harvested points of interest. May be null.

definition WorldMapDefinition

The scene's map definition, for landmarks baked into it. May be null.

fog FogOfWarMap

The explored map, for the discovery rule. May be null.

forWorldMap bool

True for the world map, false for the minimap.

labelTier int

The highest detail tier whose names are drawn; deeper tiers draw their icon without a name. See LabelTierForZoom(float, float).

Remarks

The details come first because they are where points of interest live now (PointsOfInterest): harvested by every cache rebuild whether or not a map is baked. The definition's list is what a baked scene carried before, and while a bake is present it holds the same hand-placed landmarks again, so a definition entry with the same name at the same place (to the metre) as one already added is skipped.

Two gates, and a point must pass both. The Cartography tier (VisibleContentTier, 0 to MaximumDetailTier) decides whether the point is known at all; every point-of-interest tier (0 to 3, PointOfInterestKinds) is inside that range, and with no Cartography provider every tier is shown. The discovery rule hides a point until the fog has revealed its chunk; every generated point requires discovery (2026-10-10).

Remarks

Only unlocked waypoints are appended, and fog plays no part: a waypoint the character has not discovered is absent from the map even when the ground it stands on has been explored. Walking past one is not finding it; using it is. That is what keeps a waypoint a thing to look for rather than a dot that appears on approach.

LabelTierForZoom(float, float)

The deepest detail tier whose names the world map draws at a zoom.

public static int LabelTierForZoom(float zoom, float mapHalfExtent)

Parameters

zoom float

The view's half-extent, in world metres.

mapHalfExtent float

Half the longer side of the scene's map, in world metres.

Returns

int

0 to 3: 1 when the whole scene is in view, 3 once zoomed in to a quarter of it or closer.

Remarks

A generated scene holds dozens to a hundred and more points of interest, and every name at once is a wall of text. The icons stay, so nothing found is lost; names arrive as the view closes in: settlements and great sites (tiers 0 and 1) at any zoom, ordinary sites (tier 2) from half the scene, small features (tier 3) from a quarter.
