The client's name requests of one kind: who is waiting on which ID, which IDs are due to be sent, and when each was last sent. Pure bookkeeping: no network, no Unity, main thread only.

Remarks

Coalesced, not sent per ask. Asking for a name used to send one request per ID the moment it was asked for, so opening a 100-member roster sent 100 requests in one frame (hot-path audit M18). An ask now only queues its ID; TakeBatch(double, int, List<long>) hands out the queue a batch at a time, and the caller sends each batch as one request.

Sent again on a later ask, never on its own. The server answers a request over its connection's budget with nothing, and a request sent to a scene server the client has since left is never answered either. An ID still waiting RetrySeconds after it was sent is queued again by the next ask for it, so a lost request costs one retry window and not the session. Nothing re-sends by timer: a name nobody asks for again is not worth the traffic.

"No such entity" is an answer. ResolveMissing(long, double) drops the callbacks that were waiting (they captured UI rows and characters, and would otherwise be held for the session while every later ask appended to the chain) and holds the ID's retry window, so a caller that asks for a deleted character every frame costs one request per window.
