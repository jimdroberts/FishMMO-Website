Remarks

Three passes, after post-processing, so the colour lands exactly as chosen (no tonemapping, grading or bloom) and before the UI:

  1. Mask (RGBA8): each outlined renderer drawn flat, rgb its colour and alpha its width. Fragments behind the scene's depth are dropped, so only the visible parts are outlined.
  2. Nearest in the row (R8): for each pixel, the signed column offset to the nearest mask pixel in its row within the outline radius, or none.
  3. Ring: for each pixel outside the mask, the nearest mask pixel over the column (offset² + row²: the exact Euclidean nearest within the radius), blended onto the frame with an antialiased edge at the width that pixel carries.

The two full-screen passes do their work only inside the screen rectangle the outlined renderers' bounds cover, widened by the radius; everywhere else they return at once. With nothing outlined, no pass is added at all; with the target off screen, none is recorded.

Only the main camera (tagged MainCamera) and the scene view draw outlines: the minimap and other utility cameras do not.

Every texture is RGBA8 or R8 (Firefox's WebGPU cannot sample R16), and every read is a texel load at the pixel's own coordinate, so nothing depends on samplers or on which way up a target is stored.
