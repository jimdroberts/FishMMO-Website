Remarks

This panel renders the server's answer and never its own guess. Every request it sends leaves the slot looking exactly as it did, marked as waiting, until the equipment container is replicated back — see HandleSlotRightClick(int) for what that replaced and why.

Everything a SLOT does — joining the operation tracker, deciding whether a slot is available, painting the icon and the stack badge and the lock overlay, keeping the tooltip honest, starting a drag, abandoning what is in flight — comes from UITKSlotPanelBase, which this panel shares with the bag and the bank. It used to be a second copy of all of it, eighteen identically named members, and it had drifted from the grid version in three ways; that class records which, and OnSlotPointerDown(PointerDownEvent, int) below carries the one that was a player-visible bug.

What is genuinely this panel's own is the half a socket does differently: its slots are AUTHORED in UICharacterSheet.uxml rather than built from a container's slot count and a drop onto one is an equip rather than a swap. Everything else the sheet draws — the ten sockets' contents, the character preview, the HP / MP / Stamina chips, the attribute rows — is CharacterSheetView's, which this window shares with the inspect window and which is why the two now read as one window showing two characters instead of two windows that happened to be about equipment.

The camera is handed back rather than simply left enabled, because the preview's cost is paid every frame whether or not anyone is looking at it. The base decides WHEN this is — including the Escape and quit-to-login paths, which reach Hide(bool) directly rather than through Hide() — and abandons the pending marks and any half-finished drag afterwards. OnSlotUpdateReceived(int)

Invalidates the preview framing when a socket has changed.

protected override void OnSlotUpdateReceived(int slotIndex)

Parameters

slotIndex int

Remarks

Equipment changes the silhouette: a two-handed weapon reaches further than a dagger, and a frame sized before it existed crops it. Re-framing on the next frame rather than this one is deliberate — the mesh is attached by the visual controller in the same call chain, and measuring before it lands would measure the old silhouette again.

A hook rather than part of the shared update, because it is the one thing a socket update does that a bag-slot update has no equivalent of. It runs only for an update the shared path accepted, which is where it sat before.

OnTick()

Refreshes the character preview while the panel is on screen.

protected override void OnTick()

Remarks

The preview is refreshed here rather than on the equipment events because a preview shows an animating character: the idle pose moves every frame, and a texture rendered once when the panel opened would freeze it mid-stride. A frame is also when the viewport's layout first becomes measurable, so this is the hook that gets the preview its size on the opening frame. The base ticks the operation tracker.
