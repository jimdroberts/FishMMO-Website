Remarks

The deadline lives on the server's database row as an absolute UTC instant. Comparing that instant with DateTime.UtcNow, as the world and scene servers used to, compared the scheduler's clock with this host's: a host a minute fast stopped a minute early, a clock stepped forward by NTP stopped the server at once, and the world server and the scene servers clearing its players each counted down to a different moment. Every read of the row now carries the seconds left as the database measured them in the reading statement, and this class anchors that on the monotonic clock at the moment the reply arrived.

Each reading can only place the deadline late, never early. The database measured the time left before the reply travelled back and was handed to the caller, so a reading's anchor, arrival + remaining, is late by that round trip. While the scheduled instant is unchanged, the earliest anchor seen is therefore the best estimate, and a later reading only ever tightens it. A different instant is a new schedule and starts over.

A pure object with no Unity or network dependency, so the rule is pinned by tests. Not thread-safe: each server adopts readings on its main thread.
