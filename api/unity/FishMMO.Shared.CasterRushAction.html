Remarks

Wire it to the ability's OnSpawn. The rush itself is the caster's movement (BeginMotion(Vector3, float, float, float)): predicted on the owner, authoritative on the server, reconciled as motor state. The way it goes is the caster's movement heading for this tick (the replicated aim turned onto the body), which both peers hold.

Re-applied on a replayed tick (ReappliesOnReplay). A correction for a tick before the cast takes the rush back with the rest of the motor state, and the replay of the cast's tick must start it again or the owner stands still for a round trip and then jumps. This is the case BaseAction's warning about teleports does not cover: the effect lives in state the correction restores.

Players only: an NPC is moved by its NavMesh agent, not a motor, so an NPC casting this strikes from where it stands. Refused while rooted or incapacitated.

ReappliesOnReplay

True when this action must run again on a REPLAYED tick for an effect on the caster itself to survive a correction: what it changes is state the correction has just set back (a resource, a buff), and running it again from that state gives what the prediction had.

public override bool ReappliesOnReplay { get; }

Property Value

bool

Remarks

Asked only for an event marked TickEventData.ReapplyOnly (a self-cast ability's effects, re-dispatched on replay by AbilityObject.RunSelfTargetEffects). False by default, and that is the safe answer: an action whose effect a correction does NOT take back (it grants an item, summons, teleports, plays something) would do it a second time.
