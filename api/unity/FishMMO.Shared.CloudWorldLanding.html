Remarks

Pure: a world's islands and a scene's cached details in, a place out. The server asks it whenever it is about to put a character somewhere in a cloud world it did not walk to: a respawn at a bind point, a resurrect of a body the deck has, an immortal character fished back out of it.

Why a bind point is asked about at all. Anywhere else a bind point is ground by construction, since a bindstone binds where the character stands. A cloud world's scene can be re-cut over an old one, and a bind point recorded on the old ground can be open air now; respawning there drops the character straight back into the deck, which kills it, which offers the same respawn again.

An island's reach is its outline's widest, so "over an island" is generous at a ragged edge. That is the right way to be wrong here: every authored place on an island passes, and only open air between islands fails.
