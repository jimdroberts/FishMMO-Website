Remarks

Equipment is predicted. The owner does not ask the server to equip and wait; it queues the request with RequestEquip(Item, int, InventoryType, ItemSlot) or RequestUnequip(ItemSlot, InventoryType), the request rides the next replicate, and both the owner and the server apply it inside that tick's replicate body. The server's reconcile then confirms the socket. A stale reconcile — one describing a tick before the request — is restored and the replay re-applies the request, exactly as it does for movement and abilities. The reliable acknowledgement that used to carry the answer is gone; there is nothing left for it to answer.

The one message that survives is the unequip destination (EquipmentUnequipItemBroadcast, server to owner only): the container picks the slot an unequipped item lands in, and although both peers pick deterministically they can disagree when their copies of the container differ. ApplyUnequipDestination(long, InventoryType, int) moves the item, by identity, to the slot the server chose.

Remarks

Applies immediately on whichever peer calls it. Server-side paths that are not the owner's predicted request — ECA actions, for instance — call this directly; the owner learns of the change through the reconcile. The owner's own requests must go through RequestEquip(Item, int, InventoryType, ItemSlot) instead, so they run inside the replicate tick.

RequestEquip(Item, int, InventoryType, ItemSlot)

Queues an equip to be applied on the owner's next replicate tick.

sourceIndex int

fromContainer InventoryType

The container it is in.

socket ItemSlot

The equipment socket it is going to.

Returns

Remarks

Owner only. Validates what can be validated locally — the item is where the request says, it fits the socket, it has a database identity, neither slot is locked — and refuses without queueing when it cannot. One request is held at a time; a second call before the first has ridden a replicate replaces it, and the displaced request is reported through OnRequestResolved as not applied.

OnRequestResolved

Fired on the owner when a queued request has run in the replicate body, whether or not it was applied. Arguments: the kind, the socket, the container the request named, the container index (or -1 for an unequip), and whether the move happened.

event Action<EquipmentRequestKind, ItemSlot, InventoryType, int, bool> OnRequestResolved

Event Type

Action<EquipmentRequestKind, ItemSlot, InventoryType, int, bool>

Remarks

This is how a panel that marked two slots as waiting learns that nothing will change them. A refusal here is LOCAL — the item was no longer where the request said, or the socket did not fit it. A refusal by the SERVER is not reported through this event at all: it arrives as a reconcile that puts the item back, which updates the slots directly.
