Remarks

What is being bounded. The owner resolves its projectile against characters where it draws them; the server resolves the same sweep against where its position history says they were drawn. The history reproduces the owner's view exactly while a character moves steadily and its updates arrive on time. It cannot when the owner drew something the server never had: the straight line between two position updates two ticks apart while the character turned between them, a character held at its last update because the next was late, a position rounded to the wire's centimetre grid. Every one of those errors is a DISTANCE THE CHARACTER MOVED over a tick or two, so the tolerance is a small constant plus a few ticks of the victim's own speed: a character standing still gets almost none, because nothing about a still character can have been drawn elsewhere.

Why geometry and not a physics query. The check needs one distance between one swept shape and one character, against a pose out of the history. Moving the character there, syncing physics and casting would cost a rewind scope for an answer two segments give exactly, and could not be tested without a physics scene.

Remarks

Two for the straight line a client draws between updates two ticks apart, and a half for an update that arrived inside the playback margin. A character that outran this was drawn somewhere the connection, not the aim, put it; the claim is refused and the server's own sweep stands.
