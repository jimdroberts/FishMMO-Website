BeginMotion(Vector3, float, float, float)

Starts an ability rush: for durationSeconds the character is driven across the ground along direction fast enough to cover distance, facing it, whatever its input says.

public bool BeginMotion(Vector3 direction, float distance, float durationSeconds, float tickDelta)

Parameters

direction Vector3

The way to rush; only its horizontal part is used.

distance float

How far, metres.

durationSeconds float

Over how long.

tickDelta float

Seconds per network tick.

Returns

bool

True when the rush started.

Remarks

Predicted. Called from the ability step, which runs after this character's movement step in the same tick, on the server and on the owner alike (and again on a replayed tick: the ability re-applies it). The rush is then motor state, reconciled through MotionTicks/MotionSpeed/MotionYaw, so a correction from inside it continues it rather than dropping it.

Speed and heading are quantised here (centimetres per second; 1/65536 of a turn), so the values both peers drive are the values the wire carries. A rush ends early when something stops it (FishMMO.Shared.KCCController.TickMotion()), and never starts while climbing, swimming or flying.

EndMotion()

Ends an ability rush now, from inside the movement step (stunned, rooted): a replay reaches it by itself.

public void EndMotion()

EndMotionFromHit()

Ends an ability rush because a hit stopped it: from OUTSIDE the movement step, where the ability object resolves its hits.

public void EndMotionFromHit()

Remarks

On the owner the stop is remembered, against the movement tick it followed. A hit is not run again when the owner replays a correction, so a correction from before the hit used to replay the rush straight past the target, and the server's own stop then snapped the charger back to it a moment later. The remembered stop is applied again when a replay passes its tick (ReapplyPredictedRushStop(uint)) or when a correction lands past it with the server still rushing (OnReconciled(uint)), and forgotten once the server's state shows the rush stopped there (or after ExpiryTicks, when the server never struck: then the server's rush is the truth).

On the server it is simply the stop; the reconcile carries it.

SetInputs(ref KCCInputReplicateData, bool)

Applies a tick's replicated input, optionally with the controls taken away.

public void SetInputs(ref KCCInputReplicateData inputs, bool controlsSuppressed)

Parameters

inputs KCCInputReplicateData

This tick's replicated input.

controlsSuppressed bool

True to ignore the player's controls this tick.

Remarks

With controlsSuppressed set the move vector is zeroed, no jump, crouch or sprint is honoured and a jump requested on the previous tick is forgotten, but the facing is left where it was and the motor is still driven this tick. That is what a dead or incapacitated character needs: gravity and the ground keep acting on it, the player just cannot steer it. The virtual camera is still recorded so the aim origin is current the moment control returns.

SettleRotation(Quaternion, bool, Quaternion, bool)

The rotation, or exactly the upright heading it is turning to once it is within SettleDegrees.

public static Quaternion SettleRotation(Quaternion rotation, bool hasHeading, Quaternion heading, bool upright)

Parameters

rotation Quaternion
hasHeading bool
heading Quaternion
upright bool

Returns

Quaternion

Remarks

The turn is an exponential approach (a Slerp toward the heading every tick, then a Slerp back to upright), and in floats it never lands: a character standing still kept a rotation that changed in its last bits on every tick. The reconcile carries the rotation exactly, so that noise made every reconcile of an idle player differ from the last and none could be skipped as a repeat (CharacterPredictionController quiet reconciles). Settling exactly on the heading gives a fixed point instead. Server and owner run this same arithmetic on the same input, so it is no less deterministic than the approach it ends. Only when the character turns upright (no bonus orientation), the only case with a single heading to settle on.

SettleVelocity(Vector3, Vector3)

The velocity, or exactly zero when the character is coming to rest and is slower than SettleSpeed.

public static Vector3 SettleVelocity(Vector3 velocity, Vector3 target)

Parameters

velocity Vector3
target Vector3

Returns

Vector3

Remarks

The slow-down is an exponential approach too: without this the velocity of a character that let go of the keys took seconds of ever-smaller float noise to reach zero, and each of those ticks was a reconcile that could not be skipped. A tenth of a millimetre per second is far below anything drawn; both peers run the same arithmetic.
