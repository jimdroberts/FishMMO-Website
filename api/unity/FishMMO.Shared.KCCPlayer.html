Field Value

ObserverPredictionWindowTicks

How many ticks past the last real input an observing client may keep re-simulating that input before it stops carrying it forward.

public uint ObserverPredictionWindowTicks

Field Value

uint

Remarks

Currently inert. The block that reads this only runs for a non-owner, non-server peer, and a client is never handed another character's replicate input while state forwarding is off — Replicate_NonAuthoritative returns before invoking the replicate body, and forwarding is 0 on all 39 networked objects in this project. Observers see other players through NetworkTransform instead. So changing this value has no effect today; it becomes live only if forwarding is enabled.

The value would then want to be near the client's buffered-input depth — about 6 ticks at 200ms and tick rate 30 — because a window of 1 lets an observed character stall for a tick whenever an input is late. It is a plain public field serialized on all nine character prefabs, so raising it means editing those prefabs, not this default.

TickAimOrigin

The eye at the START of the tick last simulated (before this tick's move): the point shots of that tick are fired from (AbilityController reads it, Order 100, after the motor has moved).

public Vector3 TickAimOrigin { get; }

Property Value

Vector3

Remarks

The start of the tick because that is the only eye the owner knows when it builds the input. The aim is converged from it (AimConvergence: eye to the crosshair's point), so the shot reaches that point only if it is fired from the same eye. Fired from the eye after the move instead, as it used to be, the shot ran parallel to the converged line, displaced by the tick's movement: about 20 cm sideways for a running strafe.

Recorded first thing, before any early return, on every pass including replays: the server, the owner and every replay reach the same motor state at the start of a tick, so they read the same eye.

Remarks

The owner always reconciles — this is the correction that repairs its own predicted movement.

A non-owner only reconciles a forwarded object, because that is the only mode in which the reconcile is what positions this character on an observing client. With forwarding off, position arrives through NetworkTransform and applying a motor state on top would give the transform two writers — the same failure ApplyObserverTransportMode() exists to prevent in the other direction. See ObserverSyncMode.

ResolveOwnerAim(Vector3, Quaternion, out Vector3, out Vector3, out short, out AimLaunch)

The owner's aim from a camera pose: the eye the next tick's shots leave from, the quantised direction from it to the point under the crosshair, and the body's heading offset (AimConvergence).

public void ResolveOwnerAim(Vector3 cameraPosition, Quaternion cameraRotation, out Vector3 eye, out Vector3 aimDirection, out short headingOffset, out AimConvergence.AimLaunch launch)

Parameters

cameraPosition Vector3

The camera.

cameraRotation Quaternion

The camera's rotation.

eye Vector3

The eye at the start of the next tick (TickAimOrigin once it runs).

aimDirection Vector3

The quantised aim, exactly as the wire carries it.

headingOffset short

The body's heading offset from the aim, as the wire carries it.

launch AimConvergence.AimLaunch

The launch line: the crosshair's own line, as the wire carries it (AimConvergence.LaunchLine).

Remarks

The one definition of "where the shot goes", used by the input (PopulateInput(ref CharacterReplicateData)) and by the target the crosshair highlights (TargetController.Update). Both trace the same line, so the target shown under the crosshair is the one the cast's own trace finds: over the shoulder the camera can see past a corner the eye cannot, and a highlight taken along the camera's ray would offer a target the shot can never reach.

UpdateCamera(float, float, Vector3)

Updates the camera with scroll and look input, over deltaTime seconds.

public void UpdateCamera(float deltaTime, float scrollInput, Vector3 lookInputVector)

Parameters

deltaTime float

Seconds since the camera was last updated.

scrollInput float

Scroll/zoom input.

lookInputVector Vector3

Look input vector.

Remarks

The time is the caller's FRAME time. This is called once a frame, and it used to hand the camera the length of a tick whatever the frame took, so everything the camera eases (the zoom, a boom let out after an obstruction) ran nearly five times too fast at 144 frames a second and at the authored speed only at 30. The caller passes it in because no file of the prediction path reads a wall clock itself.
