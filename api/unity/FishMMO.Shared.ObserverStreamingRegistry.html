Server-side scheduler that applies ObserverStreamingPolicy to every registered character: scales each one's observer range by local density, and for every viewing client ranks what it can see and rate limits everything beyond the cap.

Remarks

Characters register from CharacterPredictionController.OnStartServer — players, monsters, pets, and the service NPCs built on the same prefab stack — because their NetworkTransform and other per-tick traffic is what an observer's bandwidth is spent on. Static classified objects (world items, waypoints) have no such hook and are adopted by ObserverBudgetCondition on first evaluation, so that every classification can be budgeted; they cost a position read per pass and nothing on the wire.

Runs one pass every RescheduleIntervalTicks ticks off FishNet.Managing.Timing.TimeManager.OnPostTick. A pass is O(entries) for density (uniform grid) plus, for ranking, each viewer against the objects in the grid cells within reach of it (the widest admitting range and the AI's declared proximity reach) and every wide-range object, with entries grouped by Unity scene so characters in different scenes never compare positions. Before the grid it was every viewer against every object: at 200 players and 700 characters, ~140k pair evaluations per half second.

MinimumHiddenTicks

Least time, in ticks, a character the byte budget took out of view stays out before the budget may let it back in: 3 s at 30 Hz. The mirror of MinimumVisibleTicks: at the budget's edge a crowd otherwise left and came back every few seconds, and each return was a full spawn. Never applies to a pinned character (party, target, a fight) or to one within the viewer's engagement range, which come back at once.

MinimumVisibleTicks

Least time, in ticks, a character the budget let in stays in view before the budget may take it out again: 5 s at 30 Hz. Remarks

These have no CharacterPredictionController to register them from, so the call comes from ObserverBudgetCondition the first time the object is evaluated: that condition runs on the server for every object carrying the manager's defaults, and it already holds the NetworkObject. The first evaluation defers (the object is unranked, which is admitted) and the next scheduling pass ranks it — the same deferral a freshly connected viewer gets, and the reason neither shows as a pop-in.

Only objects that declare a ClassifiedDistanceCondition are taken. Anything else has no budget to be measured against, and registering it would cost a per-pass position read for a decision that would always be "admit".

RequireViewerProximity(float)

Declares the farthest nearest-player distance a reader of TryGetNearestViewerDistance(NetworkObject, out float) compares against (squared, as the AI's LOD bands are authored). Within the largest one declared, the measurement is exactly the distance to the nearest player; beyond it, it is some distance beyond it (possibly NoViewerDistance), which every such comparison reads the same way.

public static void RequireViewerProximity(float sqrDistance)

Parameters

sqrDistance float

Squared distance, metres². Infinity or NaN keeps every distance exact.

Remarks

Each viewer only measures the objects within this reach (and its ranking ranges) instead of every object in the scene. Until anything declares a reach the measurement is exact at every distance, as it always was.

The reach only grows: a reader must declare before the object it reads is first measured (an asset's load is early enough), and nothing can take reach away from a reader that already declared.

Returns

bool

True when a pass has measured this object.

Remarks

The proximity primitive server-side simulation should ask, in place of NetworkObject.Observers. Observer membership answers "who is this object being streamed to", which the visibility budget bounds — a monster outside every viewer's budget has no observers and is still standing in a crowd. This answers "how close is the nearest player", which is what a leash, a wake-up or an aggro sweep actually wants to know.

False when the object is not registered, or when no pass has measured it yet. Callers must not read that as "nobody is near": it is an unanswered question, and the answer arrives within one RescheduleIntervalTicks.
