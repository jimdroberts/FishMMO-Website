Remarks

A character's state reaches its observers one of two ways, and exactly one of them must be active at a time:

  1. Forwarded. NetworkObject.EnableStateForwarding is on, so FishNet relays the owner's replicate input and the server's whole CharacterReconcileData to every observer, and observers simulate their peers. Exact, and expensive: measured at ~2,610 B/s per observed peer against ~409 B/s for the alternative, scaling with observers times entities. Intended for small, precision-critical scenes — an arena or a tournament match.
  2. Interpolated. Forwarding is off. The reconcile goes to the owner alone, position arrives through NetworkTransform, and each controller publishes what observers actually need through its own change-gated broadcast. This is the open-world mode.

Why this type exists. The two systems overlap completely. Turning forwarding on without silencing the broadcasts does not merely pay for both — for equipment and buffs it produces conflicting writes, because the reconcile path and the broadcast path build different objects for the same slot and build items carrying different identities for the same slot. Every push site and every reconcile consumer asks this type whose turn it is, so the flag is a real switch rather than a trap for whoever flips it.

The flag is read live, never cached. SetStateForwarding can flip at runtime, and every FishNet send path reads the property per send, so these helpers do too. A controller that cached the answer in OnStartNetwork would keep broadcasting into a scene that had since switched modes.

Remarks

Used by reconcile consumers that mutate observer-visible state, so a non-owner applies reconcile data only in the mode where that data is the authority for it. In the interpolated mode the same fields arrive through a broadcast instead, and letting both write is what produces duplicate effects and phantom items.

Remarks

A null or unspawned object answers true. Such an object has no observers to send to, so the answer is only reached by callers that then find nothing to do — and answering false would silently disable the broadcast path for a character whose NetworkObject had not been assigned yet, which is the harder failure to notice.
