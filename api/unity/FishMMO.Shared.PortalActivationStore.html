Remarks

Plain data, no I/O. The scene server's interactable system owns the live store, fills it from the database (RestoreCharacterPage(long, string, int, ulong), RestoreWorldScene(string, IReadOnlyList<(int Index, PortalWorldState State)>)) and drains what is dirty into it; PortalGate reads and writes it through Current. Until a server installs one, Current is a store that treats every record as loaded and keeps them in memory only — so a portal behaves the same in a harness or a sim, it just forgets on restart.

Loaded is tracked separately from empty. A character with no rows and a character not read yet both have no bits; only the first may be answered "closed" (see PortalActivationRules). Likewise per scene for world rows.

Persistence without versions. Character bits reuse WaypointUnlockMask: set-only bits whose database merge is an OR, so dirty is activated & ~persisted and a bit set while a write is in flight stays dirty on its own. World openings are tracked by Covers(PortalWorldState): a confirmation clears the mark only if what was written covers what is held now. A released character whose bits are still unconfirmed keeps its entry, unloaded, until a write confirms them; a reload ORs the database rows back in.

Record keys. A per-character record is keyed by a string that is the scene name for portals, and the scene name plus KeySuffix for the sites a character has discovered: the same bit pages, persisted by the same rows.

Main thread only.
