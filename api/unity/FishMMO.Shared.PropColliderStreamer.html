Puts a scene's baked prop collision into physics only where something can touch it: within ServerRadius of every character on the server, and within ClientRadius of the camera on the client. A chunk (CellMetres square) at a time, as one mesh: every collidable prop in it merged and cooked off the main thread, then handed to one static collider.

Remarks

Why stream. A generated scene has tens of thousands of trees and rocks. Baked into chunk meshes on disk their collision is every prop's geometry over again, tens of megabytes per scene, all of it in physics all the time, on a server that hosts many scenes mostly far from any player. Streamed, a prop kind's collision mesh is shared, a prop is an instance record, and physics holds only the chunks near someone.

One collider per chunk. A chunk's props become a single mesh (one per collision layer present), so physics holds one static actor per chunk rather than one per rock: the merge (PropColliderStreamer.MergeJob) and the cooking (PropColliderStreamer.BakeJob, BakeMesh(EntityId, bool)) both run as jobs, and the main thread only applies the merged data and assigns the cooked mesh.

Radii. The client's covers its view distance (100 m) and a margin, so effects, projectiles and the camera meet every rock in sight. The server's covers each character's own reach, players and NPCs alike, so an NPC in view never walks through a rock the client draws. A character that appears has the chunks round it built at once (AddFocus(Transform, float)), before its first step; farther chunks follow, nearest first, at most ChunksPerTick started per tick.

Held by cell, counted. Which chunks are wanted is kept by PropChunkLedger: each focus holds the chunks round the cell it stands in, recomputed only when it crosses into another cell, and a chunk stays while any focus holds it. Holding by cell is a superset of the chunks round the focus's exact position, and a chunk is let go only ReleaseMarginMetres beyond the radius, so collision is never in fewer places than a per-tick recompute round every exact position would put it.

Each collider in its own scene. Colliders are created in the prop's scene, so a server running each world scene in its own physics scene finds them in the right one.
