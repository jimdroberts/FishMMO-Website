The content a scene fetches for itself after it has loaded: its terrain arrays, biome templates, river flow and the like, each an Addressable load a component starts from its own lifecycle. Those run outside the scene load and outside AddressableLoadProcessor's batches, so nothing that waits on either sees them. The client's loading screen holds world entry until this is empty, so the player arrives in a finished world instead of watching ground and water arrive from the cache or the web server.

Remarks

A load is a token: Begin(string) when the fetch starts, End() on every way it can finish (success, failure, the owner disabled or destroyed). End is idempotent, so an owner can call it from both its completion callback and its teardown without counting twice. A forgotten End holds the overlay only until the loading screen's own deadline, never forever.

Work. Content that has arrived is not finished: a biome registering makes the grass and scatter take their terrains again, and props merge into pools, each a few milliseconds a frame. A system with such work adds a SceneContentLoads.Work probe once (AddWork(string, Func<bool>, Func<float>)); the loading screen keeps the world covered while any probe says it is busy, and while it does (Covered) those systems spend Budget(double) a frame instead of their usual slice, so the work finishes behind the overlay rather than as hitches on the screen after it.

Progress. Loads begun while others are in flight are one wave: the bar reads the wave's finished loads plus the running ones' progress over all it has begun, so it only moves forward as loads join and end.
