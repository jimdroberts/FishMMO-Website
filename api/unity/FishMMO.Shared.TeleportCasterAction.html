Remarks

Wire it to the OnSpawn of a PointBlank ability (an invisible object at the caster's feet). The departure effect is an ordinary PlayFXAction before this one in the same event, played at the object, which stays where the caster stood. Because the object is what observers are sent, every client sees both ends of the blink.

One destination on every peer. It is measured from the cast's spawn pose (the caster's feet and facing on the tick it cast, which the server sends observers exactly), or from the caster's own pose on a replayed tick, where the object is not made again and the pose is the same one. A capsule the size of the caster's is swept along the ground a step high, so a blink stops at a wall rather than passing it, and then dropped onto the ground there.

The move runs on the server and the owner (TeleportTo(Vector3)) and again on a replayed tick (ReappliesOnReplay): the caster's position is motor state, so a correction for an earlier tick takes the blink back and the replay of the cast's tick must put it back. Refused while rooted or incapacitated. Players only: an NPC's body belongs to its NavMesh agent.

ReappliesOnReplay

True when this action must run again on a REPLAYED tick for an effect on the caster itself to survive a correction: what it changes is state the correction has just set back (a resource, a buff), and running it again from that state gives what the prediction had.

public override bool ReappliesOnReplay { get; }

Property Value

bool

Remarks

Asked only for an event marked TickEventData.ReapplyOnly (a self-cast ability's effects, re-dispatched on replay by AbilityObject.RunSelfTargetEffects). False by default, and that is the safe answer: an action whose effect a correction does NOT take back (it grants an item, summons, teleports, plays something) would do it a second time.
