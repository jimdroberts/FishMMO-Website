Remarks

Why a component at all. Unity's terrain engine binds four splat textures per pass and knows nothing of arrays, so something has to give every tile the rest through UnityEngine.Terrain.SetSplatMaterialPropertyBlock(UnityEngine.MaterialPropertyBlock). A property block is not serialized, so it is pushed whenever this enables — on scene load, after every domain reload, in edit mode as in play mode (ExecuteAlways) — and again when a tile's alphamaps are replaced (a layer added in the terrain inspector) or the scene's arrays are rebaked.

Painting stays live. The alphamaps are still the weights everything edits; each tile's index map is baked from them on the GPU (TerrainIndexMapBaker) when it is bound and, in the editor, again whenever they change (a brush stroke, a repaint, an undo), so a stroke is on screen the same frame. A scene may carry up to MaximumLayers layers and a pixel still reads four index texels.

Stored for play. In play (the editor's and a player's) a tile takes the index map the cut stored with the scene (IndexOf(TerrainData)) instead of baking one, while it is still the alphamaps' own — the same texels, so the ground looks the same either way — and a client build may then leave the alphamaps out (ClientTerrainLayerStripper). A tile with no usable stored map is baked from its alphamaps as before.

The arrays are found by the scene's name (TerrainArraySet): off disk in the editor, by address in a player. Nothing here holds a reference to them, because they are build output that each machine regenerates.

Client only. The object carries ClientOnlyObject, so server builds strip it with everything it references (and it destroys itself on a server that was built some other way), and in a server player this compiles to nothing but its serialized fields — a headless server has no use for a texture.

Remarks

A backdrop baked before it had control maps still uses URP/Lit and is left alone. Looked up on every push rather than kept, because a rebake swaps the material's shader under the same renderers. While the scene is still loading (OnEnable runs then) its roots cannot be listed, so the backdrops are found among the loaded objects instead; they are all deserialized before any OnEnable.
