The terrain's index map: for every texel of a tile's alphamaps, its four strongest layers and their weights, packed into eight bytes. What the array terrain shader reads in place of the alphamaps themselves, so a scene may carry up to MaximumLayers layers at the cost of four texel reads a pixel, however many it has.

Remarks

Why. The shader used to read every control map of a tile (four layers each) per pixel and keep the four strongest: 32 layers were eight maps and eight samples a pixel, and every layer more another map (2026-10-16: "every biome has unique textures for everything" needs far more than 32 layers a scene). The four strongest are found once per texel instead, here, and the pixel blends the four texels around it.

A texel is two 32-bit words (R32G32_UInt): x the four layer ids, a byte each, strongest first; y their weights in bytes, each LESS the texel's fifth-strongest weight. That is the shader's seam-free rule (FishTopLayers) applied at the texel: a layer that drops out of the four does so at zero, so neither the bake nor the blend jumps where a fifth layer overtakes the fourth. Ground with four layers or fewer at a texel is stored exactly as painted.

Ties go to the lower layer index, as the old per-pixel loop met them (it took the layers in index order and only a strictly greater weight moved one). Slots a texel has no layer for hold zero-weight layers, the lowest indices first, so the four ids of a texel are always distinct — the filter merges the four texels' entries by id.

The filter (Filter(uint[], int, int, float, float, int[], float[]), FishTerrainIndexMap.hlsl): ids cannot be filtered by the hardware, so the four texels a bilinear sample would read are loaded, each texel's weights scaled by its bilinear share, entries of the same layer summed, and the four strongest kept less the fifth, normalised — the old rule on the merged weights. Where every texel of the four has four layers or fewer, the merged weights ARE the bilinear weights of every layer, so the result is the old shader's exactly. Where a texel had a fifth layer, the blend there is the old one at that texel's centre and stays continuous between centres; it differs from the old per-pixel choice by at most the texels' own fifth weights.

Baked on the GPU from the live alphamaps (TerrainIndexMapBaker, FishTerrainIndexBake.shader) while the ground is edited, so a brush stroke is on screen the same frame. This class is the same bake on the CPU — the reference the GPU bake is checked against, the bake the cut STORES with the scene's terrain (TerrainDetailBake.IndexMap, what a player binds, so client builds need not ship the alphamaps), and the tests' — and the shader's filter, line for line.
