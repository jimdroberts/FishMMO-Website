The arithmetic of per-tile terrain layers (TerrainTileLayers): which of a tile's alphamap channels it keeps, the compacted alphamaps, and how a tile's channel numbers become the scene's layer ids wherever the ground is read by layer (the index map bake, the ground colour, the grass's surface layers). Pure, so the tests run it without Unity.

Remarks

Why. Every tile of a cut used to carry the scene's whole palette: Moron 2's 210 layers are 53 control maps of 512² RGBA with mips, 74 MB a tile, when no tile paints more than 62 of them (measured over the saved tiles, 2026-10-27). A tile now keeps exactly the layers it paints: those with a non-zero weight byte anywhere on it. No weight changes, so every texel — the ones on a seam too — holds the bytes it held, and two tiles meeting at a seam agree there as before, whatever either keeps. Dropping light layers by a threshold as well was measured and refused: 1–5% fewer maps for a visible change.

The scene's numbering stays the truth. The texture arrays, the layer table, the index maps, the backdrop's channels and the path slices all count the scene's layers (the binder's provenance, one entry per array slice). A tile's channel c is scene layer SceneLayers[c], its channels kept in scene order, so ties between equal weights still go to the lower scene layer as they did. Null means a tile that carries the whole palette in scene order (every scene cut before this): channel and scene layer are the same number.

MaximumTileLayers

The most layers a tile may still paint after it is compacted, where the cut reports an ERROR: 24 control maps (33 MB a 512² tile). The busiest tile measured paints 65 (Moron 3 1_1, 2026-10-27).
