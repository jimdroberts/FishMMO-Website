Remarks

Pure functions over plain values. The server is the only authority — every rule here is re-evaluated by TradeSystem on every request and again at the moment of completion — but the owning client asks the same questions first so a refusal costs no round trip, and so its window closes the instant the players separate rather than on the server's next range check.

Kept free of session state on purpose. What is on the table, who has accepted, and which version is current live on the server in TradeSession; this file answers only "may these two trade at all" and "what does this request mean".

HasRoomFor(IItemContainer, TradeOfferEntry[], TradeOfferEntry[], out int, out int)

Estimates whether a bag can take everything the other side is offering, once the bag's own whole-stack offers have left it.

public static bool HasRoomFor(IItemContainer bag, TradeOfferEntry[] incoming, TradeOfferEntry[] outgoing, out int requiredSlots, out int availableSlots)

Parameters

The receiving inventory.

requiredSlots int

Empty slots the bag will have.

Returns

bool

True when requiredSlots fits in availableSlots.

Remarks

A pre-check, not the decision. The exchange itself (TradeExchange) is all-or-nothing and refuses for room on its own; this exists so the player is told "not enough bag space" when they press Accept rather than after both have accepted. It is deliberately CONSERVATIVE in one direction only — it may say there is room when a merge order the container chooses differently would find none, in which case the exchange still refuses safely — and it never says there is no room when there is.

Stacks merge only into unlocked stacks of the same template with spare capacity, and only when the template does not generate per-item attributes (generated items carry a seed and do not stack across seeds). Anything left over needs ceil(remaining / MaxStackSize) empty slots. Empty slots counted are the unlocked empty ones plus the slots this side's whole-stack offers will vacate.

TryResolveOfferAmount(Item, uint, out uint)

Turns a requested quantity into the quantity that will actually be offered.

public static bool TryResolveOfferAmount(Item item, uint requested, out uint amount)

Parameters

item Item

The item in the slot.

requested uint

What the client asked for; zero means the whole stack.

amount uint

The quantity to put on the table.

Returns

bool

True when the request resolves to a positive quantity the item can supply.

Remarks

A non-stackable item is offered whole: the only acceptable requests are "whole" (zero) and one. A stackable item is offered whole for zero, and otherwise for the requested amount, which must fit inside the stack — asking for more than is there is refused rather than clamped, because a client that asks for 50 of a stack of 20 is either stale or lying and either way the server should not guess.
