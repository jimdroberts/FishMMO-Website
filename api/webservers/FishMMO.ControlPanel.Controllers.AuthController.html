Remarks

The password never reaches this controller. The browser runs SRP-6a against the same parameters the game client uses and sends a public ephemeral and a proof; the challenge endpoint takes a username and nothing else.

Nothing here is audited: it is a player (or an operator) authenticating as themselves, on anonymous or TwoFactorPending endpoints the audit filter excludes.

Remarks

Every panel session on the account is revoked, this one included, and this browser is given a fresh session that has proven the password only. It becomes a signed-in session through 2fa/reset/confirm with a code from the new authenticator, and not before.

Remarks

The cookie is deleted whatever happens, but "signed out" is only answered once the session row is revoked. Deleting the cookie ends this browser's copy; the row is what ends every other copy of it, and a logout that reported success while the row lived on left a copied cookie working until the idle timeout.

Remarks

A locked account, a wrong password, an unknown account and a banned one all answer 401 with GenericFailure. The one different answer — 403, stage verification-required — is given only after a CORRECT proof, so it reveals nothing to anyone who does not already hold the password.
