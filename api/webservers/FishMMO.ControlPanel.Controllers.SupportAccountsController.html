Remarks

Moderation sits at SupportStepUp rather than at Operator: banning is a game master's daily work, and requiring an administrator for it means the person actually handling the report cannot act. The step-up is what makes that safe — a borrowed unlocked session cannot ban anybody without the authenticator.

Every action here is recorded by AuditActionFilter. Nothing in this file calls an audit method; it assigns to AuditScope only where it knows something the filter cannot.

What is deliberately absent. No password reset: an operator who can set a password can sign in as the player, and SRP exists so that nobody holds a credential they can replay. A player who has lost their password uses the recovery path. No account deletion either — it would take the audit record of that account's history with it.

Remarks

A report read in isolation is how the fifth complaint about the same player gets the same warning as the first. This puts the pattern beside the report.

The moderation rows are the audit log, narrowed to this account and its characters. The full log stays Operator-only; a game master reading who banned this player before is doing the job, and reading everyone's actions is not. The actor's address, session and the free-form details are left out for the same reason. Tickets above the reader's tier are filtered in the query, as they are in the queue. Recorded in the audit log, like every staff read.
