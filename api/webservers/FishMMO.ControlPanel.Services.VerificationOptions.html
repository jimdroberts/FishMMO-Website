Remarks

A player chooses the channels they verify with at registration — email, SMS, a Discord DM, or several — and a code goes out on each one this server switches on. Any one correct code verifies the account. More channels give the player more ways to receive a code, never more codes to enter. Which channels an account is actually sent and asked for is AccountVerificationRules, shared with the login server, not anything decided here: when nothing the player chose is switched on, the account falls back to one that is, so switching a channel off never lets an account in without a code.

A server with every switch off verifies nothing, and registration takes the same auto-verify path the development AutoVerifyAccounts setting takes — one mechanism, not two. These switches must match the login server's VerifyEmail, VerifySms and VerifyDiscord, or an account could be let into the game and refused by the panel, or the other way round.

Unlike the development bypass these are honoured in Production. They are a deliberate shard policy ("this shard does not verify phone numbers"), not a convenience that must not escape a laptop, and a shard that turns them all off is told so loudly at startup.

Remarks

Only meaningful with the Discord bot running: the panel issues the code, and the bot delivers it. Switched on with no bot, a player who chose only Discord is asked for a code nobody sends, and the rule's fallback cannot help, because Discord counts as switched on.

Remarks

The bot can only message members of a server it shares with the player, so the player has to join first. It is published only when it is an https:// link; anything else is dropped at startup rather than rendered as a link on an anonymous page.
